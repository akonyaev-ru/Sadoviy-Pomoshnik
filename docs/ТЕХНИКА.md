## 1. Технологический стек

| Слой | Технология | Обоснование |
|------|-----------|-------------|
| Язык | Python 3.12 | Проверен в этой мастерской на `Hunter CLI`; на машине стоит |
| Управление браузером | Chrome DevTools Protocol по WebSocket (`websocket-client`) | Не тянет Selenium и Playwright — меньше зависимостей и вес `.exe` |
| Внедрение кода | `Page.addScriptToEvaluateOnNewDocument` | Вставляет скрипт при **каждой** загрузке страницы: то, чего не умеет закладка, и главная причина делать программу |
| Интерфейс помощника | HTML/JS **внутри страницы игры** (`src/panel.js`) | Возвращает привычный вид: кнопки там же, где были у расширения, а не в отдельном окне |
| Интерфейс программы | Без консоли: журнал в файл и окна Windows (`MessageBoxW`) | Игроку нечего читать в консоли; с ним программа говорит окнами, с разработчиком — журналом. *В контракте 1.0 было: «Консоль (`rich`)» — от неё отказались ещё в сентябре.* |
| Сборка | PyInstaller, один `.exe` | Как `Hunter CLI`: игрок запускает файл, ничего не устанавливая |
| Проверка | Стенд-подделка игры + `pytest` | Позволяет гонять красный цикл **без игрока** — см. раздел 7 |
| Выпуск | GitHub Actions, `windows-latest`, по тегу | Файл собирает чистая машина из коммита тега — см. раздел 8 |

### 1.1 Почему не расширение и не закладка
- **Расширение** — та же единственная точка отказа, из-за которой всё и
  случилось: магазин Google. Своё, неопубликованное, требует «режима
  разработчика» и ругани браузера при каждом запуске.
- **Закладка** — работает и уже собрана (`tools/ustanovka-zakladki.html`),
  но её надо нажимать заново после каждой перезагрузки страницы.
- **Программа** снимает и то и другое: ни от кого не зависит и вставляет код
  сама при каждой загрузке.

### 1.2 Где живёт помощник
Основной путь — **приложение upjers Home** (Electron, то есть тот же Chromium): программа запускает его с
`--remote-debugging-port`, и вход игрока остаётся его собственным — ничего не вводится заново. Отдельный
Chrome со своей папкой профиля — только по явному `--target browser` (проверки и запасной путь).

*В контракте 1.0 было (§2.2 «Известное неудобство»): программа всегда поднимает Chrome со своей папкой
профиля, и игрок один раз входит в игру внутри неё. Это описание теперь верно только для `--target browser`.*

## 4. Интерфейсы

Своего сервера и API нет, поэтому вместо OpenAPI — три стыка.

**Командная строка** (`si-helper`, она же собранный `.exe`):

| Ключ | Что делает |
|------|-----------|
| `--version` | печатает версию и выходит, журнал не трогает |
| `--target auto\|app\|browser` | куда селиться; `auto` — приложение upjers Home, без него — остановка с объяснением |
| `--app путь` | путь к `upjers Home.exe`, сильнее любого поиска |
| `--no-straight` | не заходить в игру самим, оставить портал как есть |
| `--force-close` | закрыть приложение принудительно — **теряет вход в игру** |
| `--script panel\|razvedka` | что вставлять в страницу |
| `--url`, `--chrome`, `--profile`, `--port`, `--host-rules` | для отдельного Chrome и проверок |

Коды выхода: `0` — работа закончена; `2` — нет вставляемого скрипта; `3` — не найдено приложение
(или Chrome при `--target browser`); `4` — отладочный порт не открылся; `6` — приложение не закрылось.

**Отладочный протокол браузера (CDP)** — цели типа `page` (оболочка приложения и вкладки) и `webview`
(в нём приложение показывает игру). Вставка — `addScriptToEvaluateOnNewDocument` в каждую цель, обход
целей раз в секунду.

**Самоотчёт панели** — `window.SI_HELPER.sostoyanie` («в саду…», «спрятан…», «жду игру…»): программа
пишет его в журнал при каждой перемене и по нему решает, открыта ли игра.

Устройство самой игры, на которое опирается `panel.js`, — `docs/game-api.md`.

## 5. Запуск и жизнь рядом с приложением upjers Home

1. **Найти приложение:** заметка прошлого запуска → обычные места → любая подпапка папок с программами →
   работающий процесс → реестр → ярлыки. Не нашли — окно «где искал» и выход: тихого Chrome нет.
2. **Приложение уже работает:**
   - с отладочным портом (открывали мы) — подключаемся, ничего не перезапуская;
   - без порта — закрываем штатно его же командой `upjers://quit` (вход сохраняется; на вопрос
     «Действительно закрыть» отвечаем «Закрыть» в его окне) и открываем с портом;
   - штатно не вышло — просим игрока закрыть через значок у часов и ждём «ОК».
3. **Главный цикл** — раз в секунду: вставка во все цели, заход в игру с «Моих игр» один раз за запуск,
   самоотчёт панели в журнал. Игра не открылась за минуту — одна подсказка «войдите как обычно».
4. **Окно-вопрос приложения** (с 2026-11-01). Пока игры нет, раз в 3 с ищем у процессов приложения
   видимые диалоги Windows (класс `#32770`; сам список процессов — раз в 30 с, `tasklist` дорог) и читаем
   их текст через UI Automation — вопрос рисует DirectUI,
   `GetWindowText` его не видит. Про память («памят», `memory`, `Speicher`) — окно: закрыть лишние
   программы и нажать «Да»; другой вопрос — «ответьте в его окне». Сами не отвечаем. После такого окна
   подсказку «войдите как обычно» не показываем: причина уже названа.
5. **Самообновление** (с 2026-11-01). Приложение закрылось — ждём до 90 с, не поднимется ли оно само с
   `--updated` в командной строке (признак берём из `Win32_Process.CommandLine`; по одним номерам процессов
   остатки закрытого приложения не отличить от нового запуска). Поднялось — через 5 с закрываем штатно и
   открываем с портом, как в п. 2; не больше трёх раз за запуск. Не поднялось — «Закрыто. До встречи.».
   Замок одного запуска на время ожидания отпускаем: игрок, щёлкнувший по значку в эти секунды, получает
   обычный запуск, а этот помощник, увидев занятый замок, уходит.
6. **Второй запуск помощника** при живом первом — не ошибка: выводим окно игры вперёд или говорим, что оно
   в трее. Спрятанное в трей окно снаружи не достаём — оно рисуется криво.

## 6. Как игра устроена — РАЗОБРАНО ПО ЕЁ ИСХОДНИКУ

> Раздел перестал быть предположением 2026-09-09: исходник игры
> (`js/wurzel_all.js`, 1,26 МБ) отдаётся без авторизации, скачан и разобран.
> **Подробности — в `docs/game-api.md`**, здесь только то, что определяет
> устройство помощника.

- Игровая страница — `main.php?page=garden` на серверах `s1.…`, `s2.…`;
  фреймов с игрой нет, всё лежит на самой странице (Prototype.js).
- Клетки — **`#gardenTile<N>`**, сетка 17 в ширину. Схема 2012 года
  `#b1..#b204` мертва.
- Действие над клеткой — **`gardenjs.action.cache(n)`**: это ровно то, что
  делает клик мышью. Игра сама копит очередь и шлёт пачками по шесть.
- ⚠️ **До вызова `cache()` клетки отсеиваем сами.** У неё есть ветки,
  срабатывающие ДО проверки режима: платный снос постройки (`category 'u'`),
  молчаливая прополка, платное ускорение. Слепой обход всех 204 клеток их
  запускает — именно это случилось на живом аккаунте 2026-09-09.
- ⚠️ **`waterAll()` не вызывать** — серверный полив «одним запросом»; поливальщик игры у игрока заперт,
  поливаем сами. **`harvestAll()` — только при нанятом жнеце**, `watergarden.harvestAll()` — когда его
  кнопка свободна: платит не вызов, а наём (замерено 2026-09-14). *В контракте 1.0 было: «`waterAll()` и
  `harvestAll()` не вызывать — почти наверняка платная возможность».*

### 6.1 Водный сад — отдельный объект, а не ещё один сад

- Это `watergarden` (класс `WatergardenClass`) со **своей** сеткой
  `watergarden.grid`, **своей** очередью (`do=watergardenCache`) и своими
  правилами: клетка бывает `water`, `edge` или `blocked`; растения лежат
  категорией `'w'`, украшения `'wd'`, сорняк `'u'`.
- Признак того, что он открыт: `watergarden.isOpen`, а также
  `window.currentGarden === 101`.
- **`gardenjs` при этом продолжает держать предыдущий обычный сад**, которого
  игрок не видит. Работать через него в водном саду — значит действовать
  вслепую по чужому саду. До 3.4.0 помощник делал ровно это.
- Полка водного сада выкладывает семена категории `'w'`; счётчик семян
  приходит ОТВЕТОМ сервера, а не уменьшается сразу, как в обычном саду.

### 6.2 Сады и город

- Переключение сада — `waehleGarten(N)` → `gardenjs.change(N)`; сколько садов
  куплено — `citymap.data.garden_count`. **Открыть некупленный сад со стороны
  браузера нельзя**, покупка идёт через `citymap.buyGardenCommit`.
- Город — `zeigeStadtMain(1)` (рынок) и `zeigeStadtMain(2)` (карта).
- Место для столбика садов — **`#asd`**: узкая полоса у правого края поля
  (20 × 640, `right:0`) в собственном `style.css` игры. Там их держал CupIvan,
  начиная с `top:250px`, и игрок помнит их именно справа.

### 6.3 Листок попрошайки

- Листок рисует `wimparea.show(id)`. Данные приходят ответом на
  **`verkaufajax` + `do:getData`**: `{id, sum, products:[{pid, amount, name}],
  neighbours}`.
- ⚠️ **Игра кэширует листки** (`q[i].sheet`) и на сервер ходит один раз на
  попрошайку. Поэтому перехвата одного лишь ajax мало: чтобы знать, ЧЕЙ листок
  открыт сейчас, слушаем ещё и `wimparea.show(id)`. Иван перехватывал только
  ajax — на возврате стрелкой к прежнему попрошайке это дало бы чужие числа.
- Товары рисуются в `#wimpVerkaufProducts` (класс `blau` — товара хватает,
  `rot` — нет), сумма — в `#wimpVerkaufSumAmount`.
- ⚠️ **К сумме игра прибавляет бонусы** и показывает уже увеличенное число:
  `D = Math.ceil(sum * (1 + бонус))`, бонус складывается из `specialbonus` и
  `birds`. Считать процент от голой `sum` значит считать не от того числа,
  которое видит игрок.
- Кнопка «Да» (`#wimpVerkaufYes`) активна, только когда хватает ВСЕГО.
- Размеры листка — из `style.css` игры: `#wimpVerkauf` 320×400, список на
  `top:90`, сумма на `top:310`.

Птичья почта и пасека — `docs/game-api.md`, разделы «Птичья почта» и «Пасека».

## 7. Как проверяем без доступа к игре

Правило доказательности из конституции требует запуска, а не слов. Доступа к
саду у агента нет, поэтому цикл строится так:

1. **Стенд** (`tools/stand.html`) — подделка игры с сеткой 204 клетки и
   игровыми объектами. Уже поймал два дефекта в разведчике, включая один
   ложный зелёный.
2. **Оболочка программы проверяется целиком на стенде**: запуск браузера,
   подключение по CDP, вставка кода при каждой загрузке, нажатие кнопок,
   возврат результата. Это настоящий красный цикл, и он не требует игрока.
3. **Игровой слой** отделён в тонкий адаптер: всё, что знает про `#b1..#b204`,
   `ajaxRequest` и прочее, лежит в одном месте и заполняется по отчёту
   разведчика. Так неизвестность локализована, а не размазана по коду.
4. К игроку уходит только то, что зелёное на стенде.

Дополнения после контракта 1.0:

- **Мутации.** Новое правило считается проверенным, когда его намеренная поломка краснит проверку:
  стенд не раз оказывался добрее игры, и вскрывали это мутации, а не чутьё.
- **Окна Windows** (`s_oknami`) — проверки, которые открывают настоящее окно или диалог. На машине
  сборки (`CI=true`) идут всегда, у себя — с `SI_OKNA=1`.
- **Собранный файл** — `python tools/check_exe.py "dist/Садовый помощник.exe"`: именно тот файл, что
  отдаём. Без аргумента скрипт берёт старую рабочую сборку и проверяет не то.
- **На Mac** проверки, которым нужна сама Windows (`tasklist`, `netstat`, мьютекс, диалоги), не проходят
  или пропускаются; остальное идёт с Chromium, если положить в `PATH` скрипт `chrome`, запускающий его.
  Ссылка вместо скрипта не годится: Chromium ищет свои библиотеки рядом с ней. Окончательная проверка —
  CI на Windows.

## 8. Выпуск

Правим версию в `src/si_helper/__init__.py` и в шапке `src/panel.js` → коммит → **лёгкий** тег
`vГОД.N` → `git push origin master vГОД.N`. Дальше `.github/workflows/release.yml` на чистой
`windows-latest`: сверка версии с тегом, `pytest`, сборка, `check_exe.py` по собранному файлу,
публикация `Sadoviy-Pomoshnik.exe` с пустым описанием. Красное на любом шаге — выпуска нет. Нумерация
календарная: `2026.1`, `2026.2`, …
